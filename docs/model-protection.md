# 示例模型的署名、来源记录与水印

**当前选择：允许署名使用和修改，禁止冒认作者。** 本页把这个目标落实为来源记录、明确的素材条款和可选水印；不额外加入禁止商用、直播或再分发的限制。Pink Sakura 的指定素材已选择 [CC BY 4.0](../examples/pink-sakura/LICENSE.md)，实际文件范围与署名方式由该示例的许可和来源记录明确。

**实施状态：保护方案设计。** 本页没有安装或验证隐水印，也不表示示例图集已加水印。发布时应把下文的实施记录补全，区分已执行与待验证项目。

## 先确定公开模型能保护什么

能够在本地播放的 `moc3`、纹理 PNG 和配置文件一旦公开，接收者就能复制这些文件。网页预览同样会把运行资源交给浏览器；隐藏下载按钮不会阻止资源被保存。水印可以提醒署名、帮助寻找来源，但不能让一个公开运行包变成不可提取的模型。

本示例选择可复现和署名再利用，因此可以在明确许可后公开参考图、拆层配方和运行包。这样也意味着别人能从源码重建没有可见水印的版本：我们依靠保留来源和修改记录的义务，而不是声称水印无法移除。若未来另一个模型要求不公开可重建素材，应另行选择只展示渲染视频/图片的发布方式；不要一边发布干净源图，一边承诺水印能防止取得干净模型。

| 方法 | 在本示例中的作用 | 不能据此宣称 |
| --- | --- | --- |
| 素材许可证与署名文件 | 说明可用范围、应保留的署名和修改记录 | 自动阻止违规复制 |
| 小型可见署名 | 在展示画面中提醒角色来源 | 无法裁剪、修补或重建 |
| 像素隐水印 | 实验性地找回示例标识 | 单独证明作者身份或权属 |
| SHA-256 清单 | 核对下载文件是否与记录逐字节一致 | 识别经过改图、截图后的所有副本 |
| 签名来源记录 | 把声明、文件指纹与发布者联系起来 | 证明声明内容天然真实，或限制播放 |

## 让署名随运行包一起交付

建议每个可分享示例包附带 `ATTRIBUTION.md`、单独的素材许可证、来源清单和版本信息。运行包里的署名应能脱离整个仓库阅读，包含项目名、仓库链接、示例版本、原始图像来源、模型制作过程、修改者及其修改说明。README 和预览页面链接到同一份署名记录，避免互相矛盾。

新粉色角色的图像来源按提供者说明标注：**“此图片来自 ChatGPT Image2.5 生成”**。记录中注明这是用户提供的来源信息，尚未独立验证生成服务记录。角色原图的生成、用户的设定与选图、后续拆层/绑定/超分工作分别说明；不能把生成图冒写为某人的手绘，也不能把修改者自己的贡献抹去。

代码和素材的许可范围分别写清：kit 的独立代码与文档使用根目录 MIT；psd2live 补丁和集成遵守其 GPL 许可；具体角色图片、纹理和模型按示例自己的素材条款分发。参见 [第三方声明](../THIRD_PARTY_NOTICES.md)。不要用素材条款重新限制本来按 MIT/GPL 分发的代码。

打包时可以明确指定两份随包文本；它们不必放进模型资源目录：

```sh
python3 scripts/package-model.py \
  --model work/character/hd/Character.model3.json \
  --core-report work/character/core-hd-report.json \
  --output work/character/release \
  --attribution work/character/release-attribution.md \
  --asset-license work/character/release-asset-license.md
```

两项参数分别复制为运行包根目录的 `ATTRIBUTION.md` 和 `ASSET-LICENSE.md`，包含在同一 ZIP 中。
输入须为非空 UTF-8 `.md` 或 `.txt`；脚本检查与运行依赖的大小写/目录冲突，核对实际复制字节，
并在 `release-metadata.json` 的 `files` 中记录 SHA，在 `attribution`、`assetLicense` 中记录是否携带及路径。
省略参数时不会自动搜索或加入源目录里的其他文件；原有的精确 Core 报告要求保持不变。

**随包文本应能独立阅读。** 仓库示例的许可文档包含相对仓库路径，不能直接原样复制后宣称 ZIP 内链接都有效。
准备发布版文本时，把仓库来源改成完整公开 URL，把两份随包文件的交叉链接改为实际固定文件名；
写清此次运行资产的许可范围及生成/修改记录。脚本只验证文本格式和字节身份，不判断许可是否正确或外链是否有效。

## 可见水印：作为可选的小型署名

推荐先提供带小型署名的展示版本，保留干净母版用于继续制作。文字可使用 `Ariakage · live2d-agent-kit`，再由署名文件给出完整来源。署名应清楚可读，同时避开脸、眼睛、嘴和细发丝；可以试放在上身衣料及下摆两个区域，避免全身预览只剩一个容易被画面裁掉的角标。

如果目标是让署名随模型展示，应该把它烘焙进实际可见的衣料纹理，而不是单独增加一个可关闭的 Drawable、表情开关或网页浮层。烘焙本身仍可被改图移除，不应把它描述为加密或 DRM。

可见署名不是本示例的强制逐帧显示条件。再利用者可以调整或移除画面标记，并在适合媒介的说明位置合理保留署名、来源、许可和修改记录；详见 [示例素材许可证](../examples/pink-sakura/LICENSE.md)。

制作顺序沿用 [超分流程](upscaling.md)，并在最终 RGB 超分完成之后加入署名：

1. 从通过动作检查的高清母版复制一个新的发布目录，记录输入文件指纹。
2. 在实际衣料可见 texel 内放置署名，核对图集上的位置与 UV 映射；不要直接把整张图集当成一张人物立绘来放文字。
3. 保持纹理页尺寸、布局、归一化 UV 和 alpha 逐值不变；不修改脸部像素、网格或 MOC。避开透明边缘、遮罩切口和 atlas padding。
4. 检查中性位、转头、身体反向摆动和全身/半身构图，确认署名没有跨层断开、被意外遮挡或产生色边。
5. 为带署名的最终 PNG 重新计算指纹，重新跑资源检查与实际 Web 渲染；原始低清图集的超分来源 SHA 仍指向真正的原输入，不能伪造哈希来绕过来源校验。

若水印步骤改变了 MOC 字节、透明度或贴图排布，先查明原因；这种结果不再属于“只加署名”。官方 Core 检查验证运行结构，无法替代对衣料、肤色和发丝的目视检查。

## 隐水印：先做独立实验

[TrustMark 官方 FAQ](https://opensource.contentauthenticity.org/docs/durable-cr/tm-faq/)介绍了像素级标识的写入与读取：它处理 RGB，不考虑 alpha，并提供移除功能；标识也可能被伪造。因此它适合作为来源检索线索，不能单独证明作者身份。**本 kit 尚未安装或测试 TrustMark，不能宣称纹理或截图已经受到它的保护。**

对于 Live2D，图集原文件与最终画面是两种不同的检测对象。图集经过 UV 采样、网格变形、遮挡、透明混合、缩放后才变成截图；在原 PNG 中读出标识，不代表在半身直播截图中也能读出。把标识写进透明 texel 或 PNG 文本字段，更不能替代对实际可见画面的检测。

实验应在高清副本中使用公开的示例 ID，保存编码/解码器版本、参数和目标文件指纹。保留原 alpha，分别比较加标前后衣料颜色、描线和边缘。不要为提高检测率不断增强水印直到破坏角色；也不要把整张图集的成功率套用到某个裁切区域。以下数值是建议的测试条件，并非已经得到的鲁棒性结果。

| 检测对象与处理 | 建议样本 | 应记录的结果 |
| --- | --- | --- |
| 最终原始 RGBA PNG | 每张纹理页 | 预期 ID、读出 ID、解码结果；alpha 是否完全一致 |
| 透明合成后再压缩 | 浅灰/深灰背景，JPEG 90/75 | ID 是否恢复、颜色/边缘变化 |
| 图集缩放 | 原尺寸的 75% / 50% / 25% | 各尺寸独立结果，不合并成一句“抗缩放” |
| 图像裁切 | 保留 90% / 75% 区域及局部衣料 | 裁切坐标、剩余内容和检测结果 |
| 实际 WebGL 截图 | 全身、半身；中性、两侧转头、头身反向 | 渲染尺寸、姿态、背景、检测与目视结果 |
| 嘴眼组合与摆发 | 张嘴 × 微笑、眨眼过渡、两侧摆发 | 是否新增肤色色块、接缝、断发；不只检查水印 |
| 阴性对照 | 干净母版、另一张无标图、错误示例 ID | 误报与错误匹配，不只统计正确样本 |

将每个结果写成“文件级检测通过”“指定截图通过”或“未检出”，保留原始证据。未检出不等于图像没有被使用；检出也需要核对来源记录，不能自动等同于未经许可使用。VTube Studio 截图若未由用户完成验收，应保持待验收状态，不能继承 WebGL 的结论。

## 文件指纹与来源凭证

SHA-256 清单能核对精确文件；任何重编码或像素修改都会改变它。把参考图、最终纹理、MOC、配置与发布版本联系起来，有助于追溯哪个包实际经过了验证。它不是能跨截图识别角色的隐水印。

可以另行给清单做数字签名，公开验证公钥，私钥留在仓库外。不要自动生成并把私钥、恢复口令或签名服务凭据提交到 Git。仅有仓库内可被替换的清单和公钥，也不能独立证明历史发布者身份，应通过已知发布渠道核验。

[C2PA 来源凭证](https://spec.c2pa.org/specifications/specifications/2.2/explainer/Explainer.html)用于把来源声明与内容关联并检测篡改；它不保证声明本身真实，也不限制资源的复制或使用。可以作为后续可选集成，本示例目前没有执行 C2PA 签名。
