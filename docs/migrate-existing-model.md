# 给已有模型接入本地摄像头

这份指引适用于已经有 `model3.json`、MOC3 和纹理的模型。先保留旧模型的取景、参数范围和视觉基线，再接入本 kit 的面部与上半身输入。如果模型缺少眉毛等绑定，另开一版制作工程补齐，并重新验证导出文件。

这里记录了迁移中已确认的输入范围和逐层去绿问题。它不是任何旧角色的新版本验收报告；当前公开的真实设备结果属于 [Pink Sakura 摄像头检查](verification/camera-tracking.json)，不能直接作为另一模型的通过记录。

## 1. 保存旧版基线

在修改前保留一份只读副本，另建本地迁移目录，例如忽略的 `work/existing-model/`。不要覆盖还在使用的 runtime 或预览目录。

| 保存项 | 要记录的内容 | 用途 |
| --- | --- | --- |
| 源素材与制作配方 | PSD、PNG、manifest、遮罩坐标、生成器和局部修补文件的 SHA-256；引擎提交与补丁版本 | 确认新导出使用了哪些源文件和行为 |
| 旧 runtime | `model3.json`、实际引用的 MOC3、每页 atlas、physics、expression、motion 等依赖的相对路径、大小和 SHA-256 | 防止把旧模型的验收记录套到新文件上 |
| 参数描述 | 从实际 Core 读取的参数 ID、最小值、默认值和最大值；哪些参数有 Drawable 变化 | 区分输入数值改变与真实绑定动作 |
| 旧预览配置 | 逻辑画布、全身/半身/脸部取景框、输入映射、角度方向、活动范围 | 保持迁移前后的构图与操作幅度可比 |
| 视觉基线 | 同一取景下的中性、左右转头、闭眼、开口微笑、发丝摆动截图与对应参数 | 检查迁移是否改变了脸、接缝或颜色 |

SHA-256 只说明文件字节相同，不证明画面好看或绑定正确。公开报告使用相对路径；角色源图、摄像头画面、设备标识和制作机的绝对路径仍留在本地。保存原验收报告，不把其中的哈希替换成新版哈希。

若只是更换网页输入链路，可以直接使用旧 runtime，不必重新导出 MOC。若修改了源层、眉毛绑定、去绿或网格，应产生新的 runtime，并为它建立单独的证据记录。

## 2. 保留取景，显式迁移参数映射

将旧预览的 `drawing`、`regions` 与 `inputMapping` 保存为自己的 JSON 配置。`drawing.width/height` 和 `regions.*.{x,y,w,h}` 使用源画布的逻辑像素；2048² 图集升级为 8192²，不意味着这些坐标也要乘 4。不要把 Pink Sakura 的脸框、旧网页 CSS 裁切值或截图显示尺寸直接当作另一角色的逻辑取景框。字段说明见[网页模板](../templates/web-preview/README.md)。

新映射默认根据**实际加载模型的原生参数范围**计算输出。旧网页若直接把输入角度写入原生参数，迁移时同一个输入可能产生更大动作。

例如，旧 `FaceAngleX` 输入为 `[-30, 30]`，旧程序直接输出 `[-30, 30]`，但模型的 `ParamAngleX` 原生范围为 `[-45, 45]`、默认值为 0：

| 输入 | 保留默认映射的输出 | 保留旧直接映射的输出 |
| --- | --- | --- |
| −30 | −45 | −30 |
| 0 | 0 | 0 |
| 30 | 45 | 30 |

要保留旧版幅度，在已有配置的 `inputMapping` 中显式写入：

```json
{
  "inputMapping": {
    "FaceAngleX": {
      "target": "ParamAngleX",
      "inputMin": -30,
      "inputMax": 30,
      "outputMin": -30,
      "outputMax": 30
    }
  }
}
```

这是配置片段，合并时保留自己原有的 `drawing`、`regions` 和其它映射。它限制摄像头/模拟输入的输出幅度，不会改变 MOC 内的原生范围；手动原生参数滑块仍可能到达 ±45。

逐项核对其它头部与身体角度、左右眼、视线、嘴部和眉毛。默认双向输入围绕原生默认值分别映射到两侧端点；默认 `MouthSmile` 从原生默认值映射到最大值。旧版若采用别的中性位置或输出范围，同样需要显式配置。左右眼沿用解剖侧别，镜像摄像头缩略图不会交换输入；需要反向时调整输出端点，并通过实际单眼眨动确认。不存在的目标参数会被跳过，不能把这一情况记为该功能已经绑定。实现见 [`tracking-input.js`](../templates/web-preview/tracking-input.js)。

### 捕捉期间保留指定参数的默认值

有些旧预览会在捕捉时固定某个未映射参数的中性值，例如保持瞳孔形状。迁移确实需要保留这一行为时，可在预览配置顶层加入 `captureHoldDefaults`：

```json
{
  "captureHoldDefaults": ["ParamEyeBallForm"]
}
```

默认是空数组 `[]`，不额外固定任何参数。数组必须由不重复的非空参数 ID 字符串组成；当前模型不存在的 ID 会跳过，不会新建参数。保持的是实际 Core 中的原生默认值，不是固定为 0。

这项配置只在模拟、手动输入信号或摄像头捕捉运行时生效：先应用输入映射，再将列表内尚未被映射写入的参数保持为默认值。**输入映射优先于保持默认值**；如果特意列入 `ParamBreath`，保持默认值又优先于控制器原有的模拟呼吸。其它未指定的物理输出不会被这一配置接管。

“手动输入信号”仍经过捕捉控制器，与直接拖动原生参数滑块不同。停止捕捉、由原生滑块接管或查看静态姿态后，这份列表不再锁定参数，也不会改写 MOC。先比较旧版动作再选择少量必要 ID，不要用整张参数表代替迁移分析。准备脚本将该字段写为 `CAPTURE_HOLD_DEFAULTS`，由 [`CaptureController`](../templates/web-preview/capture-controller.js) 的 `holdParameterDefaults` 接收；修改配置后应在新目录重新准备预览。

## 3. 缺少眉毛绑定时，从素材处理

输入中有 `BrowLeftY/RightY`，不代表模型一定有独立眉毛。先用原生参数检查真实 Drawable 是否变化；只有参数名称或滑块数值变化还不够。

如果眉毛仍画在整张脸上，需要从可编辑源中取得左右眉毛层，补齐眉毛移动后露出的脸部底色，再建立对应网格、绘制顺序和参数关键形状。让眉毛跟随头部，但能分别抬起/压低；检查额发遮挡、肤色边缘，以及左右眉极值叠加闭眼、转头时是否露出旧眉或补丁。抠出的层与底图在中性位置应能还原已认可的脸。

只在 JSON 添加 `ParamBrowLY/RY`、给它设置范围或让识别器输出分数，都不会产生这套图像与绑定。没有可编辑源或尚未补齐素材时，准确标记“眉毛未绑定”；可以暂时关闭这两个输入映射，等新版本制作完再开启。

新增绑定后的导出顺序与普通制作一致：低分导出、检查完整动作范围、修好连续性，再执行纹理超分与高清复查。不要通过超分来修复断裂、重影或错误蒙版。见[制作流程](workflow.md)、[超分说明](upscaling.md)。

## 4. 旧绿底素材必须逐层恢复去绿行为

迁移旧配方时，导入器默认值的变化也可能改变画面。当前实现中，`solid_background` 可以从顶层继承，但 **`green_despill` 只读取每一层的属性，默认是 `false`**。仅在该层的有效背景为 `#00FF00` 且逐层显式开启时，才执行去绿。

先查清旧版哪些层确实使用了绿底与去绿。只给这些层恢复原行为，例如将以下字段加入对应的既有层对象：

```json
{
  "solid_background": "#00FF00",
  "green_despill": true
}
```

不能只在 manifest 顶层写 `green_despill: true`，也不能给所有层一概开启。原生透明 PNG、没有使用绿底的原图层、含真实绿色的画面都需要保持自身处理方式。`neutral_green_despill` 可以来自层或顶层，但只是算法选择，不会自行开启去绿。

该流程会在缩放后再次对整层颜色执行去绿，不局限于透明边缘。错误开启可能影响真实绿色；漏掉旧绿底层则可能使边缘残留绿色或让新旧图集颜色不同。用同一中性姿态逐层比较低分结果，核对 alpha、发丝边缘和衣服颜色后再超分。具体字段见 [manifest 的原生透明与绿幕输入](manifest.md#原生透明与绿幕输入)。

## 5. 在新目录准备摄像头预览

以下命令在仓库根目录运行。路径是占位示例，请指向自己的 runtime、合法取得的 Core 和网页渲染依赖。`migration-preview.json` 是前面保存并修正的配置。

```sh
python3 scripts/setup-tracking.py --directory .cache/mediapipe
python3 scripts/setup-tracking.py --directory .cache/mediapipe --verify

bash scripts/validate.sh \
  --model /path/to/your/new-runtime/Avatar.model3.json \
  --output work/existing-model/structural.json

python3 scripts/prepare-preview.py \
  --model /path/to/your/new-runtime/Avatar.model3.json \
  --output work/existing-model/camera-preview-v1 \
  --cubism-core /path/to/legally-obtained/live2dcubismcore.min.js \
  --vendor-dir /path/to/legally-obtained/vendor \
  --config work/existing-model/migration-preview.json \
  --tracking-dir .cache/mediapipe

python3 work/existing-model/camera-preview-v1/server.py --port 8861
```

输出目录必须不存在或为空，重试使用新目录；端口冲突时选择空闲端口。准备脚本不会转换模型，结构检查也不是原生 Core 验证。若重新导出了 MOC，另按[验证指引](verification.md)运行 Core 和网页动作检查。

`--tracking-dir` 会根据[依赖锁](../tools/tracking-dependencies.json)核对并复制指定的 JS、WASM、模型和 notices；不会把整个开发缓存拷贝进预览。保存生成的 `preview-manifest.json`，并核对浏览器实际请求的 MOC/atlas SHA 与本次目标 runtime 一致。官方 SDK、MediaPipe 运行库与识别模型都由使用者另行获取，不需要提交到角色仓库。

## 6. 检查校准、失追和输入接管

打开页面不会申请设备。点击“开始面捕”后让脸和双肩进入画面，睁眼、闭嘴、放松，再执行校准。只用识别器的校准，不叠加旧控制器的另一套摄像头角度偏移；校准失败时不要把旧姿态当作新正位。

先测试正视、左右转头、抬低头、歪头、分别眨眼、开口与微笑组合、分别抬眉；再看肩部侧倾和转体。髋部不在画面时，躯干俯仰缺少可靠依据，不能把中性输出记为俯仰识别通过。这里是单摄像头近似上半身输入，没有独立手臂或手指绑定。

确认遮住脸、离开画面、暂停视频解码和低帧率时不会保持陈旧姿态。当前识别结果过期上限为 350ms；控制器在 500ms 没收到有效新帧时将目标设为原生默认值，再按真实经过时间平滑回正。要检查实际原生参数，不只观察“丢失”文字。手动滑块、模拟输入与摄像头必须互斥；关闭、切换来源、页面后台或离开页面后确认所有视频 track 已结束。页面的“暂停”会冻结模型但保留设备，不等同于停止摄像头。

真实设备回归需显式开启：

```sh
PLAYWRIGHT_MODULE=/path/to/playwright \
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/path/to/chrome \
  node scripts/check-camera.cjs \
  --url http://127.0.0.1:8861/ \
  --duration 20 \
  --output work/existing-model/physical-camera-v1.json \
  --physical-camera
```

该命令实际申请摄像头，使用实时设备输入，不保存摄像头截图、录像或原始关键点。当前脚本成功执行时检查以下 16 项：

| 范围 | 检查项 |
| --- | --- |
| 启动与来源（4 项） | 同源 CSP 生效；仅打开网页不请求设备；依赖已准备；真实设备与识别器启动 |
| 识别与校准（4 项） | 真实视频帧进入脸部识别；有有效肩部样本；实际 Core 参数变化；可用脸接受正位校准 |
| 失追与接管（4 项） | 解码停帧后映射目标回原生默认值；手动控制释放设备；只开脸部模式可重启；模拟接管并释放设备 |
| 网络与清理（4 项） | 仅请求视频；没有外连通过浏览器策略；无未捕获页面错误；最终全部 track 结束且音频轨道为 0 |

脚本默认使用 `ParamAngleX` 滑块测试手动接管，并检查肩部可见样本。若旧模型使用自定义参数名或只支持面部，需要明确适配对应测试入口并标注测试范围；不能删除失败项后仍称完整 16 项通过。自动报告中“参数变化”是链路检查，不逐项证明每个器官都正确绑定；眉毛、闭眼、嘴部肤色、头发连接仍要目视复查。

## 7. 保留网络策略与新版本证据

MediaPipe 在本机处理图像，但固定版本 SDK 会尝试发送性能/使用统计，关闭识别器时也可能发送剩余日志。本 kit 的服务返回：

```text
Content-Security-Policy: connect-src 'self'
```

该策略在发送前阻止外部端点。迁移到别的服务器时必须保留等效 CSP 并重测，不能只复制网页文件后继续宣称统计不会外发。报告应分别记录外连尝试、CSP 拦截和实际发出的请求，包括识别器关闭阶段。来源说明与边界见[摄像头网络说明](camera-tracking.md#网络边界与-sdk-遥测)。

最终保存新版本的源文件、配方、MOC、atlas、预览配置、摄像头模块与依赖锁指纹，并关联本次结构/Core/Web/视觉/真实设备报告。记录测试日期、浏览器版本、实际推理帧数、可见样本、原生参数覆盖和设备清理结果；公开副本只保留相对路径与必要数值。

同一份旧 MOC 接入新网页，可以继承其文件身份，仍需重测新输入链路。重新绑定眉毛或重新导出的模型，即使外观接近旧版，也要重新检查动作与资源身份。旧版 VTube Studio 验收、Pink Sakura 的摄像头通过记录和源码包重建检查各有自己的对象与范围，不能互相替代。新模型的 VTube Studio 验收由使用者在自己的环境另行完成。
